# RAG Coda-Slack Bot

A Slack bot based on a RAG (Retrieval-Augmented Generation) architecture that allows users to query the corporate Knowledge Base hosted on Coda.io directly via chat.

## Main Features

* **Natural Language Querying:** Users can ask questions on Slack by mentioning the bot (`@Bot how do I request time off?`).
* **Slack Timeout Workaround:** Uses `slack-bolt` *Lazy Listeners* to bypass Slack's 3-second limit, ensuring the AI has the time needed to process the response.
* **Serverless RAG Engine:** Uses LangChain and **Pinecone** for vector search on documents directly in the cloud, ensuring data persistence even if the server restarts. Additionally, the engine is hosted via **Render**, a PaaS solution.
* **High-Performance LLM:** Powered by **Cohere** models (`command-r-plus-08-2024` for generation and `embed-multilingual-v3.0` for embeddings).
* **Coda Data Extraction:** Dedicated module for asynchronous polling and downloading Coda pages in Markdown format.

---

## Tech Stack

* **Programming Language:** Python 3.12+
* **Dependencies Management:** Poetry
* **Webserver:** FastAPI / Uvicorn
* **Hosting via PaaS:** Render
* **Slack Integration:** Slack Bolt Framework (`slack-bolt`)
* **AI & Orchestration:** LangChain, LangChain-Cohere, LangChain-Pinecone, LangChain-Classic
* **Vectorial Database:** Pinecone (Cloud)

## Setup and Installation

### 1. Prerequisites

* Python 3.12;

* Poetry;

* Cohere account for API key;

* Pinecone account (Create an index named `coda-rag-index` with 1024 dimensions and cosine metric.).

* An App created on the Slack API Dashboard.

### 2. Dependencies Installation

Clone the repo and install the dependencies via Poetry:

```Bash
poetry env use 3.12
poetry install
```

### 3. ENV variables

create a `.env` file in the root folder of the project and insert the following keys:

```Bash
SLACK_BOT_TOKEN=xoxb-your-slack-token
SLACK_SIGNING_SECRET=your-slack-signing-secret
COHERE_API_KEY=your-cohere-api-key
CODA_API_TOKEN=your-coda-token
PINECONE_API_KEY=your-cohere-api-key
PINECONE_INDEX_NAME=coda-rag-index
```

### ⚠️ Warning for the build (Poetry pack error)

If during installation or deployment you receive the build error `No file/folder found for package rag-coda-slack`, it means that Poetry is trying to package the project as if it were a public library, based on the data entered in `pyproject.toml` (such as `name = "rag-coda-slack"` and the Python version `~3.12, <4.0.0`).

To disable this feature and use Poetry only to manage dependencies, add this block to the end of the `pyproject.toml` file:

```Ini, TOML
[tool.poetry]
package-mode = false
alternatively, you can run the installation command using the --no-root flag.
```

### How to start the Bot locally

During development, the bot requires two open terminals: one for the FastAPI server and one to expose the local port to the internet via Ngrok.

#### Terminal 1: FastAPI server

```Bash
poetry run uvicorn src.main:api_app --reload --port 3000
```

#### Terminal 2: Tunnel start (Ngrok)

```Bash
ngrok http 3000
```

Copy the URL generated by ngrok (e.g., https://xxxx.ngrok-free.app) and paste it into your Slack App dashboard under Event Subscriptions > Request URL, appending `/slack/events` to the end.

### ☁️ Production architecture (Deploy)

The bot has been structured to be "Cloud-Native." Having no local databases, it is ideal for hosting on free PaaS (Platform as a Service) platforms.

* **Suggested Hosting:** Render.com or Koyeb.

* **Database:** Pinecone ensures that the Knowledge Base is not lost during ephemeral cloud container restarts.

* **Keep-Awake:** To prevent the free plan from going to "sleep" (causing a Slack timeout upon waking), it is recommended to use a service like cron-job.org to ping the bot's address every 10 minutes.

### How to connect Slack (Temporary with Ngrok)

#### Phase 1: Create the app

1. Go to the official developer site: [api.slack.com/apps](https://api.slack.com/apps) and log in with your Slack account.

2. Click the green **"Create New App"** button.

3. Choose **"From scratch"**.

4. Give your bot a name (e.g., Knowledge Base Bot or Coda RAG).

5. **Fundamental step:** In the **"Pick a workspace"** dropdown menu, select your work Workspace.

6. Click "Create App".

#### Phase 2: Give Scopes to the bot

1. In the left menu, click on "OAuth & Permissions".

2. Scroll down to the "Scopes" section and look under "Bot Token Scopes".

3. Click on "Add an OAuth Scope" and add these three fundamental permissions:
    * `app_mentions:read` Allows the bot to hear when someone writes `@Bot`.
    * `chat:write` Allows the bot to write and reply in the channel.
    * `channels:read` Allows the bot to see which public channels it is in.

#### Phase 3: Install it in the workspace and obtain tokens

1. Scroll to the top of the same page ("OAuth & Permissions") and click the "Install to Workspace" button.

2. Slack will ask you to confirm ("The app requests permission to access..."). Click "Allow".
   Here is your first Token! You will see a string appear starting with `xoxb-... (Bot User OAuth Token)`. Copy it and paste it into your `.env` file on the `SLACK_BOT_TOKEN` line.

3. To get the second secret, go to the left menu under "Basic Information".
4. Scroll down to "App Credentials" and click Show next to "Signing Secret".
5. Copy it and paste it into your .env file on the `SLACK_SIGNING_SECRET` line.

#### Phase 4: Management of Event Subscriptions


1. Go to the "Event Subscriptions" menu on the left.

2. Turn the "Enable Events" switch to On.

3. In the "Request URL" field, paste your ngrok URL and add `/slack/events` (e.g., https://1234-abcd.ngrok-free.app/slack/events). Wait a second and the green "Verified" text should appear.

4. Scroll down to "Subscribe to bot events", click "Add Bot User Event", and add:
* `app_mention`

5. Click the green "Save Changes" button at the bottom right. (Slack will ask you to click a yellow banner at the top to "reinstall your app" to apply the changes. Do so).

##### How to find the Bot on Slack once it got installed

The bot is now part of the workspace, but it isn't in any channels chatting yet!

1. Open your Slack application (or website).

2. Go to the channel where you want to perform the tests (e.g., #general or create a new one called #test-bot).

3. Write this message in the channel:

```text
/invite @NameOfYourBot (replacing the name with the one you gave it). 
```


Slack will add the bot to the channel.

4. Now write:
```text
@NameOfYourBot What is the training budget for a part-time employee?
```

### How to connect Ngrok

#### Step 1: Turn on the bot server (Terminal 1)

First, we need to turn on the local webserver (FastAPI) so that it is ready to listen.

1. Open a terminal in your project folder.

2. run the server on a specific port (3000 for example):

    ```Bash
    poetry run uvicorn src.main:api_app --reload --port 3000
    ```

> *if you see "Application startup complete", your bot is on and listening. Leave such window open.*

#### Step 2: Open the Ngrok tunnel (Terminal 2)

Now we need to take that port 3000 and "launch" it onto the internet.

1. Open a new terminal window (do not close the other one).

2. Run the command to start ngrok on the same port:

    ```Bash
    ngrok http 3000
    ```

3. The terminal will change screen. Look for the line starting with Forwarding and copy the secure URL (https). It will look something like: `https://123a-456b.ngrok-free.app`.

> :memo: ***Important note:** on free plans, every time you turn ngrok off and on again, this URL changes!*

#### Step 3: Address in Slack

Now let's paste this new address into the Slack dashboard.

1. Go on `api.slack.com/apps` and click on your bot.

2. In the menu on the left, go in **"Event Subscriptions"**.

3. Under **"Request URL"**, paste the address you copied from ngrok and add the endpoint we wrote in the code at the end, which is `/slack/events`..
Correct example: `https://123a-456b.ngrok-free.app/slack/events`

4. As soon as you paste it, Slack will send an invisible "ping" to test it. If everything is up and running, you will see a wonderful green <font color="green">*"Verified"*</font> text appear!

5. Click on **"Save Changes"** at the bottom right (if it asks you to reinstall the app with a yellow banner at the top, do so).

6. It's the moment of the truth!
If you see the green tick <font color="green">*"Verified"*</font>, it means that your PC and Slack are communicating perfectly.

7. Open your company Slack, go to the channel where you invited the bot, and write to it:
*@NameOfYourBot* What is the training budget for a part-time employee?

If everything went well:

    * The bot will instantly reply with "I'm consulting the Knowledge Base on Pinecone... ☁️⏳".
    *  Behind the scenes, it will query Pinecone and Cohere.
    * A few seconds later, it will write the correct answer ("250€ per year").

### 🚀 Deploy on Render (Production)

Ngrok is perfect for local testing, but to put the bot into production 24/7 you need to move it to a cloud server.

1. **Push on Github:** Upload all code to a private GitHub repository (make sure the `.env` file is ignored by `.gitignore`!).
2. **Create the Web Service:** Go to Render.com, create a new "Web Service", and connect it to your repo.
3. **Configuration:**
    * **Runtime:** `Python 3`
    * **Build Command:** `pip install poetry && poetry install --without dev --no root`
    * **Start Command:** `poetry run uvicorn src.main:api_app --host 0.0.0.0 --port $PORT`


4. **Environment Variables:** In the Environment Variables tab on Render, copy and paste all the keys you have in your local `.env`. Also add a `PYTHON_VERSION` variable set to `3.12.x` to align it with your `pyproject.toml`.
5. **Slack Update:** Once the deployment is complete, copy the new URL provided by Render (e.g., https://your-bot.onrender.com). Go to the Slack dashboard under Event Subscriptions and replace the old Ngrok link with https://your-bot.onrender.com/slack/events.

### Automatic Knowledge Base Synchronization (Coda Webhook)

To avoid launching manual updates from the terminal, you can instruct Coda to send a signal to the bot whenever the HR documents are updated.

1. Open your document on Coda.
2. Insert the official **"Webhooks"** Pack.
3. Create an **Automation** (e.g., time-based "Every day at 02:00" or triggered by a button).
4. Choose the **Post to URL** action and enter your Render bot's URL with the dedicated route:
👉 https://your-bot.onrender.com/coda-update

As soon as the automation triggers, the bot will automatically empty the Pinecone vector database and reload the updated Markdown fragments.

### Server Sleep Prevention (Keep-Awake for Slack)

Free hosting plans like Render go to "sleep" after 15 minutes of inactivity to save resources. If the bot is asleep, it takes about 50 seconds to wake up on the first message of the morning. Slack, having a strict 3-second timeout, will return an error to the employee.

To permanently resolve the issue:

1. Create a free account on **cron-job.org**.
2. Create a new Cronjob that makes a call every 10 minutes.
3. Point the URL to your bot's automatic documentation page:
👉 https://your-bot.onrender.com/docs

This page always responds with a `200 OK` without burdening the server. The simulated traffic will trick Render, keeping the bot awake, responsive, and ready to reply in real time.
